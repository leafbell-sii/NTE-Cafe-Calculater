# NTE 별미 카페 계산기 — SPEC (초안)

## 1. 개요
- NTE 「별미 카페」의 시간당 수익(폰즈)을 계산하고, 보유 캐릭터 기준으로 수익이 가장 높은 메뉴·직원 조합을 찾아주는 웹 도구.
- 게임 로직: `gameLogicData.md`
- 데이터: `FoodData.md`, `CharacterCitySkillsData.md`

## 2. 플랫폼
- 정적 웹 페이지, Vercel 배포
- 반응형 (PC / 휴대폰 모두 사용 가능)
- 한국어 UI
- 입력값 저장 없음 (localStorage, URL 공유 등 사용하지 않음. 새로고침 시 초기화)
- 기술 스택(제안): Vite + React + TypeScript, 서버 없이 클라이언트에서 모든 계산 수행

## 3. 모드
### 3.1 최적화 모드 (기본)
- 첫 화면. 입력 조건에서 수익 상위 N개 조합을 보여준다.

### 3.2 수동 계산 모드 (테스트용)
- 메뉴·직원을 직접 지정해 수익을 계산한다. 로직 검증용.
- 눈에 잘 띄지 않게 배치한다. (예: 페이지 하단의 작은 텍스트 링크)

## 4. 입력
### 4.1 공통
| 항목 | 형식 | 기본값 |
|---|---|---|
| 기본 유동인구 | 숫자 (p) | 2400 |
| 인기도 계수 | 숫자 (예: 0.015) | 0 |
| 트렌드 | 선택 (모든 트렌드: 태그 3종, 과일, 각 재료명) | 없음 |

### 4.2 최적화 모드
| 항목 | 형식 | 비고 |
|---|---|---|
| 보유 캐릭터 | 캐릭터별 체크 | |
| 캐릭터 레벨 | 캐릭터별 선택 (1~5) | 보유 체크된 캐릭터만 |
| 상위 N | 선택 또는 숫자 | 기본값 10 (가안) |

### 4.3 수동 계산 모드
| 항목 | 형식 | 비고 |
|---|---|---|
| 메뉴 | 음식 최대 5개 선택 | 중복 불가, 빈칸 허용 |
| 직원 | 캐릭터 최대 10명 선택 + 각 레벨 선택 | 중복 불가, 빈칸 허용 |

## 5. 계산 로직
- `gameLogicData.md`를 따른다. 요약:
    1. 유동인구 = `(기본 유동인구 + 유동인구 합연산 버프) × (1 + 유동인구 곱연산 버프 합)`
    2. 유동인구 계수 = `유동인구 / 100`
    3. 음식 계수 = `(가격 + 트렌드 계수 + 판매가 합연산 버프) × (1 + 판매가 곱연산 버프 합)`
    4. 최종 수익 = `총 음식 계수 × 유동인구 계수 × (1 + 인기도 계수)`
- 가게 5개는 형식상 표현이므로 계산·UI 모두에서 구분하지 않는다.
- 스킬 조건(태그 개수 등)은 선택된 메뉴 전체로 판정한다.
- 식재료 소모속도, 「점장 특제」 효과는 계산하지 않는다.

## 6. 최적화
- 탐색 범위
    - 메뉴: 전체 음식 중 5개 조합 (현재 18개 → C(18,5) = 8,568가지)
    - 직원: 보유 캐릭터 중 최대 10명 조합
        - 모든 버프가 0 이상이므로 보유 캐릭터가 10명 이하면 전원 배치가 항상 최적
        - 10명 초과면 10명을 고르는 조합 탐색 (현재 12명 → C(12,10) = 66가지)
- 방식: 전수 탐색 (현재 규모 기준 약 57만 회 계산, 브라우저에서 충분히 빠름)
    - 데이터가 크게 늘어 느려지면 Web Worker 분리 또는 가지치기 도입
- 결과: 최종 수익 내림차순 상위 N개

## 7. 출력
### 7.1 결과 목록
- 각 순위마다: 시간당 총 폰즈, 메뉴 5개, 배치 직원(레벨 포함)
- 최적화 모드는 상위 N개 카드, 수동 모드는 단일 결과

### 7.2 영수증 (펼치기)
- 각 결과에 접힌 「영수증」을 두고, 펼치면 계산 과정 전체를 단계별로 보여준다.
    1. 유동인구: 기본값 → 캐릭터별 합연산(P) 항목 → 곱연산(%) 항목 → 최종 유동인구 → 유동인구 계수
    2. 판매가 버프: 캐릭터·레벨별 합연산/곱연산 항목과 조건 충족 여부
        - 조건 미충족 효과도 흐리게 표시해 왜 빠졌는지 보이게 함
    3. 음식별: 가격 + 트렌드 + 합연산 = 소계 → × 곱연산 = 음식 계수
    4. 총 음식 계수
    5. 최종 인기도 계수
    6. 최종 수익 = 총 음식 계수 × 유동인구 계수 × 최종 인기도 계수

### 7.3 숫자 표시
- 소수점 둘째 자리까지 반올림해서 표시
- 내부 계산은 반올림 없이 전체 정밀도로 수행 (표시할 때만 반올림)

## 8. 데이터 구조 및 확장성
- 데이터는 코드와 분리된 파일로 두고, 사용자가 직접 수정한다. 데이터만 고치면 UI·계산·최적화에 자동 반영되어야 한다.
- 파일 구성 (가안)
    - `src/data/foods.ts`: 음식 목록
    - `src/data/characters.ts`: 캐릭터와 레벨별 스킬 효과
    - `src/data/trends.ts`: 트렌드 목록과 판정 규칙
    - `src/data/constants.ts`: 기본 유동인구(2400), 트렌드 계수(0.75), 최대 음식 수(5), 최대 직원 수(10) 등
- 스키마 (가안)
```ts
type Tag = '메인 메뉴' | '디저트' | '음료';

interface Food {
  id: string;
  name: string;
  price: number;
  tag: Tag;
  ingredients: string[];
}

// 스킬 효과 종류
type EffectKind =
  | 'priceAdd'    // 판매가 합연산 (폰즈)
  | 'priceMul'    // 판매가 곱연산 (0.01 = 1%)
  | 'trafficAdd'  // 유동인구 합연산 (P)
  | 'trafficMul'; // 유동인구 곱연산 (0.01 = 1%)

// 발동 조건 (모두 "이상" 판정, 충족 시 1회 적용)
type Condition =
  | { type: 'tagCount'; tag: Tag; min: number }   // 특정 태그 N개 이상
  | { type: 'sameTagCount'; min: number };        // 동일 태그 N개 이상

interface SkillEffect {
  level: number;        // 해금 레벨 (선택 레벨 이하의 효과가 모두 누적 적용)
  kind: EffectKind;
  value: number;
  condition?: Condition;
}

interface Character {
  id: string;
  name: string;
  skillName: string;
  effects: SkillEffect[];
}

type TrendMatch =
  | { type: 'tag'; tag: Tag }
  | { type: 'ingredientAny'; ingredients: string[] }; // 과일 트렌드, 단일 재료 트렌드 모두 표현

interface Trend {
  id: string;
  label: string;
  match: TrendMatch;
}
```
- 새로운 효과 종류나 조건이 생기면 `EffectKind` / `Condition`에 항목을 추가하고 계산 함수에서 처리한다.
- 재료 트렌드 목록은 음식 데이터의 재료로부터 자동 생성할 수 있다.

## 9. 범위 밖
- 식재료 소모속도, 「점장 특제」
- 가게별 배치·계산
- 입력값 저장, 공유
- 음식 해금 여부 필터

## 10. 미정 사항
- 상위 N의 기본값과 선택 범위
- 최적화 결과에서 수익이 같은 조합(동점)을 정렬하는 기준
- 트렌드 선택지에 「없음」을 둘지 여부 (현재 초안은 기본값 「없음」)
