# NTE 별미 카페 계산기 — SPEC (초안)

## 1. 개요
- NTE 「별미 카페」의 시간당 수익(폰즈)을 계산하고, 보유 캐릭터 기준으로 수익이 가장 높은 메뉴·직원 조합을 찾아주는 웹 도구.
- 게임 규칙·계산식: `gameLogicData.md`
- 데이터: `src/data/*.json` (구성은 「8. 데이터」 참고)

## 2. 플랫폼
- 정적 웹 페이지, Vercel 배포
- 반응형 (PC / 휴대폰 모두 사용 가능)
- 한국어 UI
- 입력값 자동 저장: 바꿀 때마다 `localStorage`에 저장하고, 다시 들어오면 그대로 복원한다.
    - 대상: 모드, 인기도, 트렌드, 최적화 모드의 보유 캐릭터·레벨, 수동 모드의 메뉴·직원·레벨
    - 저장 대상 아님: 「더 보기」 표시 개수, 카드 펼침 상태
    - 데이터 JSON이 바뀌어 저장값이 맞지 않으면(없어진 id, 범위 밖 레벨 등) 해당 항목만 기본값으로 되돌린다.
- 설정 공유: 하단 「설정 공유 링크」 버튼이 저장된 입력값 전체를 URL 해시에 담아 클립보드에 복사한다.
    - 형식 `#c=` (압축, 기본): 데이터 JSON의 항목 순서(인덱스)를 바이트로 담은 base64url. 구현은 `src/share.ts` 참고.
        - 데이터 JSON의 항목 순서가 바뀌면 그 전에 만든 링크는 다른 설정으로 열릴 수 있다. (새 항목은 끝에 추가 권장)
    - 하단 입력창에 공유 링크나 코드(`#c=` 뒷부분만도 가능)를 붙여넣고 「적용」하면 같은 방식으로 덮어쓴 뒤 새로고침한다. 해석할 수 없으면 「잘못된 코드」를 표시한다.
    - 형식 `#s=` (구): localStorage JSON 전체를 base64url로. 읽기만 지원하고, 압축할 수 없는 데이터 크기일 때만 생성한다.
    - 링크로 들어오면 앱 시작 전에 그 값을 localStorage에 덮어쓰고 해시를 지운다. 값 검증은 일반 복원과 같다.
- 기술 스택(제안): Vite + React + TypeScript, 서버 없이 클라이언트에서 모든 계산 수행

- 버그 제보: 하단에 구글 폼으로 연결되는 「버그 제보」 버튼 (새 탭). 주소는 `src/config.ts`의 `BUG_REPORT_URL`, 비어 있으면 버튼을 숨긴다.

## 3. 모드
### 3.1 최적화 모드 (기본)
- 첫 화면. 입력 조건에서 수익이 높은 조합을 순위대로 보여준다.

### 3.2 수동 계산 모드 (테스트용)
- 메뉴·직원을 직접 지정해 수익을 계산한다. 로직 검증용.
- 눈에 잘 띄지 않게 배치한다. (예: 페이지 하단의 작은 텍스트 링크)

## 4. 입력
### 4.1 공통
| 항목 | 형식 | 기본값 |
|---|---|---|
| 인기도 계수 | 소수 (게임 표기와 동일, 예: 0.015) | 0 |
| 트렌드 | 선택 (없음 / 범용 / 태그 3종 / 과일 / 각 재료명) | 범용 (전체 트렌드 평균) |
| 마네키네코 | 체크박스 | 꺼짐 |

- 기본 유동인구는 입력받지 않고 `constants.json`의 `baseTraffic`(2400)을 고정값으로 쓴다.
- 인기도 계수는 0 이상만 허용한다. 음수는 입력할 수 없게 막는다.
- 마네키네코: 켜면 유동인구 곱연산 버프에 `+1%`를 더한다. (다른 곱연산 버프와 합적용, 직원 슬롯과 무관) 저장·공유 링크에 포함된다.
- 트렌드는 게임에서는 항상 하나가 활성화되어 있고 무엇이 올지 모르므로, 계산기에서는 「전체 트렌드 평균 (범용)」을 기본값으로 둔다.
- 재료명 트렌드는 과일 재료를 포함한 모든 재료를 선택지로 둔다.
- 「전체 트렌드 평균 (범용)」: 어떤 트렌드가 와도 잘 버는 범용 조합을 찾기 위한 선택지. 「8.4」 참고.

### 4.2 최적화 모드
| 항목 | 형식 | 비고 |
|---|---|---|
| 보유 캐릭터 | 캐릭터별 체크 | |
| 캐릭터 레벨 | 캐릭터별 선택 (1~5, 기본값 5) | 보유 체크된 캐릭터만 |

- 결과 개수는 입력받지 않는다. 처음 5개를 보여주고 「더 보기」로 늘린다. (「7.1 결과 목록」 참고)

### 4.3 수동 계산 모드
| 항목 | 형식 | 비고 |
|---|---|---|
| 메뉴 | 음식 최대 5개 선택 | 중복 불가, 빈칸 허용 |
| 직원 | 캐릭터 최대 10명 선택 + 각 레벨 선택 (기본값 5) | 중복 불가, 빈칸 허용 |

## 5. 계산 로직
- `gameLogicData.md`를 따른다. 요약:
    1. 유동인구 = `(기본 유동인구 + 유동인구 합연산 버프) × (1 + 유동인구 곱연산 버프)`
    2. 유동인구 계수 = `유동인구 / 100`
    3. 음식 계수 = `(가격 + 판매가 합연산 버프 + 태그 트렌드 계수) × (1 + 판매가 곱연산 버프) + 기타 트렌드 계수`
    4. 최종 수익(매출) = `총 음식 계수 × 유동인구 계수 × (1 + 인기도 계수)`
    5. 식재료 비용 = `유동인구 / 100 × (1 − 식재료 소모 감소량) × Σ_A M(A)·가격(A)`
    6. 순수익 = `매출 − 식재료 비용`
- 모든 「버프」는 각 효과 값의 단순 합이며, 곱연산 버프의 `1 +`는 계산식에서 붙인다.
- 트렌드 계수는 한 음식에 최대 1회 적용된다.
- 태그 트렌드 계수는 판매가 곱연산 버프를 받는다. (인게임 확인) 재료 트렌드 계수는 받지 않는다. (인게임 확인) 과일 트렌드는 미확인이므로 재료 트렌드와 같이 곱연산 뒤에 더한다.
- 가게 5개는 형식상 표현이므로 계산·UI 모두에서 구분하지 않는다.
- 스킬 조건(태그 개수 등)은 선택된 메뉴 전체로 판정한다.
- 「점장 특제」 효과는 계산하지 않는다.

## 6. 최적화
- 탐색 범위
    - 메뉴: 전체 음식 중 5개 조합 (현재 18개 → C(18,5) = 8,568가지)
    - 직원: 보유 캐릭터 중 최대 10명 조합
        - 모든 버프가 0 이상이므로 보유 캐릭터가 10명 이하면 전원 배치가 항상 최적
        - 10명 초과면 10명을 고르는 조합 탐색 (현재 12명 → C(12,10) = 66가지)
- 방식: 상한 기반 가지치기(분기 한정)로 상위 결과만 정확히 찾는다. (「6.2 가지치기」 참고)
- 결과: 정렬 기준 값 내림차순
    - 정렬 기준: 매출(기본) / 순수익. 결과 목록 위 토글로 고르며, 저장·공유 링크에 포함된다.
    - 순위 비율, 동점 판정, 접힌 행의 1위 대비 차이도 정렬 기준 값으로 계산한다.
    - 같은 메뉴가 직원 조합만 바뀌어 여러 순위에 나오는 것은 의도된 동작이다. (캐릭터 중심 도구이므로 메뉴별로 묶지 않음)

### 6.1 동점 처리
- 수익 비교는 부동소수 오차를 고려해 `|차이| < 1e-9`이면 같은 수익으로 본다.
- **같은 메뉴 + 같은 수익**인 직원 조합들은 결과 하나로 묶는다.
    - 대표 조합 1개를 결과에 보여주고, 나머지는 「대체 가능 직원」으로 표시한다.
    - 대표 조합: 각 조합의 캐릭터를 `characters.json` 순서로 정렬해 비교했을 때 앞서는 조합.
    - 동점 직원 조합은 보유 캐릭터가 10명을 넘을 때만 생긴다. (10명 이하면 전원 배치이므로 조합이 하나뿐)
- **메뉴가 다른 동점**은 묶지 않고 각각 별도 결과로 보여주며, 같은 순위 번호(공동 순위)를 붙인다.
    - 공동 순위 다음 순위는 공동 순위 개수만큼 건너뛴다. (예: `1, 1, 3`)
    - 공동 순위끼리의 표시 순서: 메뉴의 음식을 `foods.json` 순서로 정렬해 비교했을 때 앞서는 쪽이 먼저.
- 묶인 결과는 순위·개수 계산에서 1개로 센다.

### 6.2 가지치기
- 목표: 필요한 결과 개수 `K`(현재 표시 개수 + 다음 「더 보기」 분량)만큼 **정확한** 상위 결과를 구한다. 가지치기로 결과가 달라지면 안 된다.
- 상한 계산의 근거: 메뉴가 정해지면 각 캐릭터의 효과(조건 판정 포함)는 `(판매가 합, 판매가 곱, 유동인구 합, 유동인구 곱)` 4개 값으로 고정되고, 최종 수익은 네 값 각각에 대해 단조 증가한다.
    - 따라서 남은 자리가 `r`개일 때, 남은 후보 중 **값별로 독립적으로** 상위 `r`개를 더한 값으로 계산한 수익은 실제로 가능한 어떤 조합보다도 크거나 같다. 이 값을 상한으로 쓴다.
    - 순수익 정렬: 버프에 식재료 소모 감소를 더한 5개 값을 쓴다. `순수익 = 유동인구/100 × [음식 계수×(1+인기도) − (1−감소량)×Σ M·가격]`이므로 괄호 안은 상한 값으로, 유동인구는 괄호 부호에 따라 현재 값(하한)과 상한 값 중 큰 쪽으로 계산한다.
- 절차
    1. 메뉴별 상한: 보유 캐릭터 전체에 대해 위 방식으로 상한을 구한다.
    2. 메뉴를 상한 내림차순으로 처리한다. 지금까지 찾은 `K`번째 결과의 수익을 `기준값`이라 할 때, 메뉴 상한이 `기준값 − 1e-9`보다 작으면 그 메뉴와 이후 메뉴는 모두 건너뛴다.
    3. 메뉴 안에서 직원 조합은 캐릭터를 하나씩 넣고/빼며 탐색하고, 부분 조합의 상한이 `기준값 − 1e-9`보다 작으면 그 가지를 자른다.
    4. 동점(「6.1」)을 빠짐없이 모으기 위해 기준값과 같은 수익(오차 이내)은 자르지 않는다.
- 보유 캐릭터가 10명 이하이면 직원 조합이 하나뿐이므로 메뉴 단위 가지치기만 적용된다.
- 「더 보기」: `K`를 늘려 다시 탐색한다. 이미 구한 결과는 그대로 두고 이어서 보여준다.
- `K`는 묶인 결과(같은 메뉴 + 같은 수익) 기준으로 센다.

### 6.3 소요 시간 로그
- 최적화 1회(초기 탐색, 「더 보기」 재탐색 각각)의 소요 시간을 `performance.now()`로 잰다.
- 소요 시간이 **2초 이상**이면 `console.warn`으로 로그를 남긴다.
    - 내용: 소요 시간(ms), 보유 캐릭터 수, 음식 수, `K`, 평가한 메뉴 수 / 전체 메뉴 수, 평가한 직원 조합 수
- 기준 시간(2초)은 게임 데이터가 아니므로 `constants.json`이 아닌 코드 상수로 둔다.

## 7. 출력
### 7.1 결과 목록
- 각 순위마다: 시간당 정렬 기준 값(매출/순수익), 매출·식재료 비용·순수익 요약 한 줄, 메뉴(최대 5개), 배치 직원(레벨 포함)
- 수동 모드는 단일 결과
- 최적화 모드
    - 처음에는 상위 5개 결과를 카드로 보여준다.
    - 1위 카드는 다른 카드보다 크게 강조해서 보여준다.
    - 각 순위에 1위 수익을 100%로 본 비율을 소수점 둘째 자리까지 내림해 표시한다. (예: `100.00%`, `99.99%`) 동점이 아니면 `100.00%`로 표시되지 않는다.
    - 목록 아래 「더 보기」 버튼을 누를 때마다 10개씩 더 보여준다. 더 보여줄 결과가 없으면 버튼을 숨긴다.

### 7.2 대체 가능 직원
- 동점으로 묶인 결과(「6.1 동점 처리」)에는 「대체 가능 직원」 버튼을 둔다. 동점 조합이 없으면 버튼을 두지 않는다.
- 버튼을 누르면 대표 조합에서 어떤 직원을 누구로 바꿔도 같은 수익인지 변환 케이스를 펼쳐 보여준다.
    - 각 동점 조합에 대해 `빠지는 직원 = 대표 조합 − 동점 조합`, `들어오는 직원 = 동점 조합 − 대표 조합`을 구한다.
    - 빠지는 직원이 같은 케이스끼리 한 줄로 묶어 표시한다.
    - 표기: `(빠지는 직원) -> (들어오는 직원), (들어오는 직원), ...`
    - 예
        - `(a) -> (c), (d)`: a를 c로 바꾸거나, a를 d로 바꿔도 같은 수익
        - `(a, b) -> (c, d)`: a, b를 함께 c, d로 바꿔야 같은 수익
    - 줄 순서: 빠지는 직원 수가 적은 줄이 먼저, 같으면 `characters.json` 순서.
    - 직원은 레벨을 함께 표시한다.

### 7.3 영수증 (펼치기)
- 각 결과에 접힌 「영수증」을 두고, 펼치면 계산 과정 전체를 단계별로 보여준다.
    1. 유동인구: 기본값 → 캐릭터별 합연산(P) 항목 → 곱연산(%) 항목(마네키네코 포함) → 최종 유동인구 → 유동인구 계수
    2. 판매가 버프: 캐릭터·레벨별 합연산/곱연산 항목과 조건 충족 여부
        - 조건 미충족 효과도 흐리게 표시해 왜 빠졌는지 보이게 함
    3. 음식별: 가격 + 합연산 (+ 태그 트렌드) = 소계 → × (1 + 곱연산) → (+ 과일·재료 트렌드) = 음식 계수
    4. 총 음식 계수
    5. 최종 인기도 계수
    6. 최종 수익 = 총 음식 계수 × 유동인구 계수 × 최종 인기도 계수
    7. 식재료 소모: 캐릭터·레벨별 감소 항목 → 소모 배율 → 식재료별 `사용 개수 M(A)`, 시간당 소모량 × 개당 가격 = 비용 → 식재료 비용 합
    8. 순수익 = 매출 − 식재료 비용

### 7.4 숫자 표시
- 소수점 둘째 자리까지 반올림해서 표시
- 내부 계산은 반올림 없이 전체 정밀도로 수행 (표시할 때만 반올림)

## 8. 데이터
### 8.1 원칙
- 데이터는 코드와 분리된 JSON 파일로 두고, 사용자가 직접 수정한다. 데이터만 고치면 UI·계산·최적화에 자동 반영되어야 한다.
- 규칙(계산식, 조건 해석, 트렌드 판정 등)은 데이터 파일에 두지 않고 `gameLogicData.md`와 이 문서에만 둔다.
- % 단위 값은 소수로 저장한다. (1% = 0.01)

### 8.2 파일 구성
| 파일 | 내용 | 출처 |
|---|---|---|
| `src/data/foods.json` | 음식 목록 (`Food[]`), 재료별 소모 개수 포함 | 게임 내에서 직접 적음 |
| `src/data/ingredients.json` | 식재료와 개당 가격 (`Ingredient[]`) | 게임 내 |
| `src/data/characters.json` | 캐릭터와 레벨별 스킬 효과 (`Character[]`) | `https://nte.inven.co.kr/db/esper` |
| `src/data/trends.json` | 재료 묶음 트렌드 정의 (현재: 과일) | 게임 내 |
| `src/data/constants.json` | 기본 유동인구, 트렌드 계수, 마네키네코 버프, 최대 음식 수, 최대 직원 수, 최대 스킬 레벨 | 게임 내 |

- 음식 이름은 게임 원문 표기를 따른다. 단, 「라떼」/「라테」는 「라테」로 통일한다.
- `characters.json`의 `skillText`는 사이트 원문(오탈자 포함)을 그대로 수록한다. 표시·참고용이며 계산에는 `effects`만 쓴다.
- `effects`에는 계산 대상 효과만 넣는다. (「점장 특제」 효과는 넣지 않음)

### 8.3 스키마
```ts
type Tag = '메인 메뉴' | '디저트' | '음료';

// foods.json: Food[]
interface Food {
  id: string;            // 영문 kebab-case, 고유
  name: string;          // 게임 원문 표기
  price: number;         // 폰즈
  tag: Tag;
  ingredients: { name: string; count: number }[]; // 재료명(ingredients.json), 음식 1개당 소모 개수(게임 내 표기, 0.01 단위: 밀가루 1개 → 0.01)
}

// ingredients.json: Ingredient[]
interface Ingredient {
  name: string;          // 고유
  price: number;         // 개당 폰즈
}

// 스킬 효과 종류
type EffectKind =
  | 'priceAdd'    // 판매가 합연산 (폰즈)
  | 'priceMul'    // 판매가 곱연산 (0.01 = 1%)
  | 'trafficAdd'  // 유동인구 합연산 (P)
  | 'trafficMul'  // 유동인구 곱연산 (0.01 = 1%)
  | 'ingredientReduce'; // 식재료 소모 감소 (0.01 = 1%)

// 발동 조건 (모두 "이상" 판정, 충족 시 1회 적용)
type Condition =
  | { type: 'tagCount'; tag: Tag; min: number }   // 특정 태그 N개 이상
  | { type: 'sameTagCount'; min: number };        // 동일 태그 N개 이상

interface SkillEffect {
  level: number;        // 해금 레벨 (선택 레벨 이하의 효과가 모두 누적 적용)
  kind: EffectKind;
  value: number;
  condition?: Condition;
}

// characters.json: Character[]
interface Character {
  id: string;           // 영문 kebab-case, 고유
  name: string;
  skillName: string;
  effects: SkillEffect[];
  skillText: string[];  // 레벨 1~5 스킬 원문 (index 0 = 레벨 1)
}

// trends.json
interface TrendsData {
  ingredientGroups: {
    id: string;
    label: string;          // 예: '과일'
    ingredients: string[];  // 하나라도 들어간 음식에 적용
  }[];
}

// constants.json
interface Constants {
  baseTraffic: number;    // 2400
  trendBonus: number;     // 0.75 (과일·재료 트렌드)
  tagTrendBonus: number;  // 1.00 (태그 트렌드)
  manekiTrafficMul: number; // 0.01 (마네키네코 유동인구 곱연산)
  maxFoods: number;       // 5
  maxStaff: number;       // 10
  maxSkillLevel: number;  // 5
}
```

### 8.4 트렌드 선택지 생성
- 트렌드 목록은 데이터에서 런타임에 만든다.
    - 없음
    - 태그 트렌드: `Tag` 3종
    - 묶음 트렌드: `trends.json`의 `ingredientGroups`
    - 재료 트렌드: `foods.json`에 등장하는 모든 재료 (과일 재료 포함, 중복 제거)
    - 범용 트렌드: 위의 태그·묶음·재료 트렌드 전체(없음 제외)의 평균. 목록 맨 뒤에 둔다. (공유 코드가 트렌드 인덱스를 쓰므로)
        - 음식별 트렌드 계수 = 각 하위 트렌드에서의 트렌드 계수의 평균 (곱연산을 받는 몫과 받지 않는 몫을 따로 평균)
        - 수익(매출·순수익)은 두 트렌드 계수 합 각각에 선형이므로, 이 계수로 계산한 수익은 하위 트렌드 각각의 수익을 평균낸 값과 같다. 따라서 최적화 결과는 「전체 트렌드 평균 수익」 순위이며, 기존 최적화·가지치기를 그대로 쓴다.
        - 결과 카드의 음식에는 적용되는 하위 트렌드 수를 `★N/전체` 형식으로 표시한다.
```ts
type TrendMatch =
  | { type: 'none' }
  | { type: 'tag'; tag: Tag }
  | { type: 'ingredientAny'; ingredients: string[] } // 묶음 트렌드, 단일 재료 트렌드 모두 표현
  | { type: 'average'; trends: Trend[] };            // 범용 트렌드

interface Trend {
  id: string;
  label: string;
  match: TrendMatch;
}
```
- 트렌드 `id`는 종류 접두어를 붙여 만든다. 종류가 달라도 겹치지 않게 하기 위함이다.
    - 없음: `none`
    - 태그: `tag:<태그>` (예: `tag:음료`)
    - 묶음: `group:<ingredientGroups.id>` (예: `group:fruit`)
    - 재료: `ingredient:<재료명>` (예: `ingredient:사과`)
    - 범용: `average`
- 선택 UI는 종류별로 묶어서 보여준다. (없음 / 범용 / 태그 / 묶음 / 재료, 재료는 가나다순)

### 8.5 데이터 검증
- 사용자가 JSON을 직접 수정하므로, 앱 시작 시 데이터를 검증한다. (zod 등 런타임 스키마 검증)
- 검증 항목
    - 스키마: 필드 누락, 타입, `Tag` / `EffectKind` / `Condition.type` 값이 정의된 값인지
    - 고유성: 음식 `id`, 캐릭터 `id`, 묶음 트렌드 `id` 중복
    - 범위: `effects[].level`이 1~`maxSkillLevel`, `skillText` 길이가 `maxSkillLevel`, `price`·`value`·`min`이 0 이상
    - 참조: `trends.json`의 재료가 `foods.json`에 실제로 등장하는지, `foods.json`의 재료가 `ingredients.json`에 있는지
    - 고유성: 식재료 이름 중복, 한 음식 안의 재료 중복
- 검증에 실패하면 계산하지 않고, 화면에 어느 파일의 어느 항목이 왜 틀렸는지 오류 목록을 보여준다.

### 8.6 확장
- 새로운 효과 종류나 조건이 생기면 `EffectKind` / `Condition`에 항목을 추가하고 계산 함수에서 처리한다.
